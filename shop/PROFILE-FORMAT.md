# PROFILE.md format

`PROFILE.md` lives at `$SHOP_PROFILE`. Point it into a synced git repository to share it across machines. Pincodes, addresses and phone numbers never go in it.

## Structure

```md
# Shopper

## Body and sizes
- {A measurement or size, with the purchase that proved it}

## Fit rules
- {What garment measurement in their size reads as the fit they want, per item type}

## Looks that work
- {A style, cut, collar, color or detail, in the user's words where possible, and why it works on them}

## Looks to avoid
- {What makes them look worse, and why}

## Wishlist
- {Something they want to own someday}

## Sites
- {What they think of a site: trusted for what, avoided for what}

## Purchases
### {Item name} ({site}, {month year})
- Link: {url}
- Size bought: {size}, with its size-chart measurements (chest and length for tops, waist and inseam for bottoms, foot length for shoes)
- Verdict: {how it fit and looked}
- Adjustments: {rolled sleeves, hemmed, insoles, half size up, none}
- Again: {yes / no / in another color}
```

## Rules

- **Measurements beat labels.** Record the garment measurement of the size that worked, not only the size label. Brands size differently.
- **Name the proof.** A size or fit rule names the purchase that set it, so a later search knows how firm it is.
- **Revise in place.** When a preference changes, edit the line rather than adding a contradicting one.
- **Untested is a label.** If the user is unsure about a look ("polos might work"), write it as untested, and update it once they try one.
